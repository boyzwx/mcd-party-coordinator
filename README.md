# 麦门聚餐指挥官

**一群人吃麦当劳，忌口不同、预算有限，到底怎么点才不踩雷？**

一个面向**多人聚餐**的 AI 点餐协调器，基于麦当劳 MCP 实时数据，
输出可直接下单的组合方案 + 精确到分的 AA 分摊账单。

`多人约束求解` · `零尾差分摊` · `忌口硬约束过滤`

</div>

---

## 为什么做这个

团建、聚餐、多人点单——这可能是每个打工人每周都要面对的难题。

现在的做法通常是：打开小程序，翻菜单，群里问一圈谁要什么，
有人忌口、有人想吃辣、有人只想喝可乐，一轮下来半小时过去了，
最后凑出一桌单价不低、分摊还对不上账的餐。

**更糟的是，AA 时谁多点了一个大份，剩下的人心里都不爽。**

现有的 AI 点餐工具都是单人视角的——帮**一个人**算便宜、算营养。
但聚餐本质是个**多约束冲突问题**，不是一个人能算清的。

---

## 它解决什么

以「6 人聚餐 / 预算 400/ 2 人不吃辣 / 1 人全素」为例：

|痛点 | 麦门聚餐指挥官的处理 |
|---|---|
| 忌口冲突凑不出桌| 硬约束优先过滤，全素项单独校验配料，**无解时如实告知**并给取舍建议 |
| 看着单价不高，加购就超 | 人均预算为上限，按"满意度损失最小"原则减配，先砍加购不砍主餐 |
| AA 时算不清谁多点了 | 谁额外消费谁单独承担，不做平均摊 |
| 除不尽差 0.01 元 | **整数分运算，尾差零误差**，账单总额与实付完全一致 |
| 一桌全是高油高钠 | 输出热量/钠参考值，中性提示不评判 |

## 快速开始

### 1. 配置 MCP 连接

先到 [open.mcd.cn/mcp](https://open.mcd.cn/mcp) 申请 MCP Token，然后：

```bash
export MCD_MCP_TOKEN="你的 Token"
```

在 WorkBuddy 中配置连接器（`~/.workbuddy/mcp.json`）：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

### 2. 安装 Skill

将本仓库克隆或下载后，把 `SKILL.md` 与 `scripts/` 放入你的 Skill 目录，
或直接在 WorkBuddy 中导入本仓库为 Skill。

### 3. 使用

```
6 个人一起吃麦当劳，预算 400，其中2 个人不吃辣，1 个人吃全素，帮我配一下
```

输出示例：

## 核心特性

### 零误差分摊算法

`scripts/split_bill.py` 使用**整数分**运算，彻底避开浮点误差：

```
除不尽时：386.00 ÷ 6 = 64.3333...
→ 64.34 / 64.34 / 64.33 / 64.33 / 64.33 / 64.33
  合计 386.00，与实付完全一致
```

12 个测试用例覆盖尾差、额外消费、个人优惠、大额团餐与异常输入。

```bash
python3 scripts/split_bill.py
```

### 四层约束求解

| 层级 | 类型 | 处理方式 |
|---|---|---|
| 第一层 | 忌口过敏 | **硬约束，不可违背** |
| 第二层 | 预算 | 上限约束，允许 10% 浮动 |
| 第三层 | 满意度 | 软目标，最大化匹配多数人偏好 |
| 第四层 | 营养结构 | 参考校验，中性提示 |

### 诚实原则

- 优惠券接口返回为空时，不编造"用券可省"
- 约束无解时，如实说明并给出取舍方向，不硬凑方案
- 营养数据表述为"参考值"，不构成专业建议
- 下单前必须经用户明确确认，绝不代替用户确认
